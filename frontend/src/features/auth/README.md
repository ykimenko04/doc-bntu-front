# Серверная авторизация

Контракт взят из раздела 2.2 [спецификации бэкенда](https://github.com/nik-vitebskiy/doc-bntu/blob/a2e38caefcc7b75c18ba269f2cd1113b67c3d28c/docs/frontend-integration-spec.md).
Проверен commit `a2e38caefcc7b75c18ba269f2cd1113b67c3d28c`.

**Ограничение интеграции:** в проверенном [app/main.py](https://github.com/nik-vitebskiy/doc-bntu/blob/a2e38caefcc7b75c18ba269f2cd1113b67c3d28c/app/main.py)
нет обработчиков `/api/auth/*`. Есть HTML-формы `POST /login`,
`POST /change-password` и `GET /logout`, возвращающие HTML/перенаправления.
Frontend реализован по документированному JSON-контракту; тесты подставляют
ответы этого контракта. Проверка с живым сервером ожидает реализацию API.

## Форматы

Все запросы используют `credentials: 'include'`; JWT и Authorization отсутствуют.
Логин и смена пароля отправляются как `application/json`.

| Метод                          | Тело запроса                                  | Успешный ответ           |
| ------------------------------ | --------------------------------------------- | ------------------------ |
| GET /api/auth/me               | отсутствует                                   | 200, объект пользователя |
| POST /api/auth/login           | `{"username":"…","password":"…"}`             | 200, объект пользователя |
| POST /api/auth/logout          | отсутствует                                   | 204, без тела            |
| POST /api/auth/change-password | `{"current_password":"…","new_password":"…"}` | 204, без тела            |

Объект пользователя: `{"id":42,"username":"employee","full_name":"Имя","role":"HEAD","need_password_change":false}`.
Роли: `ADMIN` и `HEAD`. Поле `full_name` преобразуется в `fullName` на границе API.
Поля email и active не добавляются в сессию: их нет в этом ответе.
Если login не вернул полный объект, вызывается me. Неполный/неверный me не открывает приложение.
Повтор нового пароля проверяется только на клиенте и не отправляется.
Ошибка API: `{"detail":"Текст ошибки"}`.

## Сессия и маршруты

[Providers](../../app/providers.tsx) проверяет me при запуске, хранит пользователя
только в памяти, удаляет старый ключ `bntu-auth`. Старые и отменённые проверки
не должны восстанавливать сессию поверх более нового состояния.
[Router](../../app/router.tsx) ждёт проверки сессии и закрывает защищённые маршруты.
При сетевой ошибке доступ остаётся закрытым, доступна повторная проверка.

BrowserRouter использует basename `/app`, Vite — base `/app/`.
Сервер должен отдавать SPA index для прямых запросов `/app/*`, включая
`/app/change-password`; API должен отвечать JSON/204, без HTML-перенаправлений.
По умолчанию API вызывается с того же origin; `VITE_API_URL` задаёт origin API,
без суффикса `/api`. При разных origin сервер должен разрешать CORS с cookie
для фактического origin frontend (dev Vite по-прежнему использует порт 5173).

При обязательной смене пароля доступны экран смены и выход; меню скрыто.
Смена пароля завершается обновлением me. Если обновление не удалось, защищённые
страницы остаются недоступны до успешной проверки. Ошибка выхода сохраняет
пользователя и показывает, что выход сервером не подтверждён; 401 означает,
что действующей сессии уже нет.

Общий [API-клиент](../../shared/api/client.ts) отклоняет ошибки, публикует
401/403 для состояния приложения, поддерживает 204 и проверяет JSON для
`/api/*`. Начальный me и login обрабатывают 401 локально.
Настройки показывают профиль с сервера только для чтения и ведут на общий экран
смены пароля, вместо локальной имитации сохранения.

## Проверки

[Тесты сессии и маршрутов](../../app/auth.test.tsx) используют настоящий provider,
router, формы и оболочку с подставленными HTTP-ответами.
[Тесты API-клиента](../../shared/api/client.test.ts) проверяют cookie, ошибки,
204, HTML, JSON и сохранение поддержки существующих загрузок файлов.

Из каталога frontend:

- `npm run typecheck`
- `npx tsc -b` (проверяет также проекты, на которые ссылается корневой tsconfig)
- `npm run lint`
- `npm test`

Перед проверкой с реальным сервером требуется реализовать четыре JSON-обработчика
и обработку session-cookie по спецификации, а также раздачу SPA на `/app/*`.
